# الأمان والخصوصية

## الحالة الحالية

النموذج الأولي لا ينشئ اتصالًا شبكيًا ولا ينقل الملفات. لذلك لا يثبت حاليًا أي ضمان أمان أو تشفير للنقل. الرسوم والعبارات عن الاتصال الخاص تصف هدف التصميم فقط.

## مبادئ المنتج

- يوافق المستلم أو يرفض قبل إرسال محتوى الملف.
- يوضح الطلب هوية المرسل والملفات أو المجلدات والحجم قبل القرار.
- لا تُرسل الملفات إلى خدمة Signaling في التصميم الأساسي؛ تستخدم الخدمة للتفاوض ومعلومات الاتصال فقط.
- قد يعمل TURN كمرحل عند تعذر الاتصال المباشر؛ يجب شرح ذلك للمستخدم وعدم الخلط بين المرحّل والتخزين السحابي.
- لا تضاف وظيفة انتظار دون اتصال أو تخزين مؤقت قبل تحديد مكان الملف ومدته وإمكانية حذفه والحصول على الموافقة.

## مخاطر يجب تقييمها

- طلبات مزيفة أو متكررة، وروابط/رموز جلسة يمكن إعادة استخدامها.
- أسماء الملفات وأحجامها كبيانات وصفية حساسة.
- فقدان الهاتف أو بقاء ملفات مستلمة في مجلد عام.
- امتلاء التخزين، ملفات غير مكتملة، أسماء متكررة أو امتدادات مضللة.
- إساءة استخدام الإشارات أو استنزاف خدمة TURN.

## شروط ما قبل الإطلاق

- مراجعة إعدادات WebRTC والتأكد من حماية قناة البيانات، والتحقق من الهوية وربطها بطلب القبول.
- تحديد عمر رموز الجلسة وإبطالها عند الرفض أو الإلغاء أو انتهاء المهلة.
- منع الكتابة فوق ملفات المستلم دون موافقة، وتنظيف الأجزاء غير المكتملة بطريقة آمنة.
- وضع حدود حجم ووقت ومعدل طلبات، وحماية بيانات الاعتماد لخدمات Signaling وTURN.
- اختبار عدم وصول محتوى الملف إلى سجلات الخادم، ومراجعة سجلات الأخطاء والاحتفاظ بها.
- نشر إشعار خصوصية صادق قبل جمع أي بيانات تشغيلية.

هذه القائمة ليست مراجعة أمنية ولا شهادة. يلزم فحص مستقل قبل استخدام ملفات حساسة أو نشر نسخة إنتاجية.
