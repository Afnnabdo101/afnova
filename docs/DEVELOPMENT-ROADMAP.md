# خارطة تطوير AFNOVA

لا توضع مواعيد قبل تحديد الجهد والموارد. ينتقل المشروع إلى المرحلة التالية بعد إظهار دليل اجتياز معايير المرحلة الحالية.

## 0. أساس المستودع والنموذج البصري — منجز

- تأسيس مشروع Flutter لمنصة Android.
- إضافة واجهة عربية RTL، منتقي ملفات محلي، ودليل المشروع المصوّر.
- تنظيم مكونات الإجراءات والميزات ضمن widgets/models، وإضافة معرض للرسوم المفاهيمية وحركة واجهة غير متكررة.
- توثيق البنية المقترحة ومصادر الأصول والخصوصية وخطة الاختبار.
- توثيق ما يعمل وما يزال مقترحًا، وإعداد فحوص Flutter الآلية.

**بوابة الإنجاز:** `flutter analyze` و`flutter test` ناجحان، والواجهة لا تعرض نقلًا أو سرعة وهمية.

## 1. اتصال جهازين وملف واحد

- تحديد خدمة Signaling بسيطة وآلية تعريف/ربط الجهازين.
- اختبار WebRTC وICE مع STUN، وتقرير الحاجة إلى TURN.
- تنفيذ طلب استقبال وقبول/رفض وإلغاء من الطرف الآخر.
- إرسال واستقبال ملف واحد مع فحص سلامة المحتوى.

**بوابة الإنجاز:** تجربة موثقة بين جهازين حقيقيين على شبكتين مختلفتين، مع اختبار الرفض وإعادة الاتصال وعدم إرسال الملف قبل الموافقة.

## 2. الاعتمادية وتجربة النقل

- دعم ملفات متعددة ومجلدات مع حفظ المسارات والأسماء.
- عرض التقدم والسرعة والحجم المتبقي من بيانات فعلية.
- تصميم الاستئناف واختبار موضع التوقف والتحقق من سلامة الملف.
- معالجة فشل الشبكة ومهلة الطلبات والإلغاء.

**بوابة الإنجاز:** مصفوفة اختبارات لأحجام وأنواع ملفات مختلفة، مع نجاح المقارنة بين الملفات الأصلية والمستلمة.

## 3. الإرسال إلى عدة مستلمين

- اختبار إرسال مستقل لكل مستلم أو توزيع ملفات واضح السلوك.
- عرض الحالة والقبول والرفض والتقدم لكل مستلم.
- تقييم حدود الأداء عند تعدد الاتصالات.

**بوابة الإنجاز:** حالات موثقة لعدة مستلمين مع بقاء حالة كل منهم منفصلة.

## 4. الميزات المستقبلية

- تقييم إشعارات أكثر تقدمًا والإرسال المؤجل.
- بحث دردشة ومجموعات فقط إذا بقيت ضمن هدف المنتج.
- دراسة دعم iOS والكمبيوتر بعد استقرار Android.

**بوابة الإنجاز:** قرار موثق لكل ميزة مع أثرها على الخصوصية والاستضافة والصيانة. لا تُضاف الميزات لمجرد وجودها في تطبيقات أخرى.
